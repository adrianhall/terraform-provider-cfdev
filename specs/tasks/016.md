# 016 — Documentation

## Introduction

Publish the public GitHub Pages documentation site for the released cfdev provider.

## Details

This is the final implementation step. Validate the released version, Registry/GitHub links, examples, and generated API docs. Write documentation acceptance checks for navigation, code samples, links, and versioned release content. Build and publish `adrianhall.github.io/terraform-provider-cfdev/` (or the final repository Pages URL) using the five-phase structure: Just get it done, Beginner, Intermediate, Advanced, and API docs.

The site must include installation and usage examples, Wrangler compatibility and transaction semantics, troubleshooting and recovery guidance, Registry/source/issues/releases links, security and contribution policies, and generated reference material. Add a GitHub Pages build and publish job to the release workflow so every new provider version regenerates, validates, and publishes versioned documentation.

Run the standard delivery loop, including final docs build, link checks, full format/lint/tests, and coverage, then commit with `docs(site): publish cfdev provider documentation`.

## Acceptance Criteria

- GitHub Pages site is published at the repository's public Pages URL.
- Documentation has the five required phases.
- Usage examples are runnable and use the released `adrianhall/cfdev` provider.
- API docs cover provider configuration and `cfdev_d1_migration` lifecycle.
- Links to Registry, source, issues, releases, security, and contribution guidance work.
- Each new provider release rebuilds and publishes versioned site content.
- Documentation checks, full tests, quality gates, coverage, and commit pass.
