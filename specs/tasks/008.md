# 008 — Atomic per-migration execution

## Introduction

Implement Wrangler-compatible per-migration execution and rollback semantics.

## Details

Validate table reads and the pinned Wrangler behavior. Write tests proving that migration SQL and its bookkeeping insert are sent in one request, failures do not record the migration, previous successful migrations remain applied, and retries select only absent migrations. Implement one-request-per-migration execution with no cross-migration transaction.

Run the standard delivery loop and commit with `feat(d1): apply migrations atomically per migration`.

## Acceptance Criteria

- Each migration runs separately and in deterministic order.
- SQL and `INSERT INTO <table> (name) VALUES (...)` execute in one request.
- A failed request rolls back its migration and bookkeeping insert.
- Earlier successful migrations remain committed.
- There is no automatic down migration or cross-migration rollback.
- Unknown commit status is surfaced for verification before retry.
- Tests, checks, and coverage pass.
