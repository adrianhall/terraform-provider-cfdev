# 009 — Terraform resource schema and planning

## Introduction

Define the Terraform Plugin Framework schema and plan behavior for `cfdev_d1_migration`.

## Details

Validate all lower-level seams and coverage. Write tests for required fields, defaults, plan-time filesystem validation, stable state, sensitive values, and migration-set hash changes. Implement resource schema and planning behavior.

Run the standard delivery loop and commit with `feat(resource): add migration resource schema`.

## Acceptance Criteria

- Required `account_id`, `name`, and `migrations_dir` fields are validated.
- `migrations_pattern` defaults compatibly and `migrations_table` defaults to `d1_migrations`.
- Invalid migration directories and patterns produce plan diagnostics.
- State contains deterministic migration identity/hash data without secrets.
- File changes produce meaningful planned changes.
- Tests, checks, and coverage pass.
