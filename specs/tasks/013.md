# 013 — Security, failure recovery, and quality gates

## Introduction

Harden diagnostics and enforce security, recovery, static-analysis, and coverage requirements.

## Details

Validate all checks and inspect diagnostics for leaked tokens or SQL. Write tests for redaction, malformed API responses, unknown commit-status guidance, concurrent-apply diagnostics, and least-privilege configuration. Implement logging, recovery documentation, static analysis, race testing where practical, and the 80% coverage gate.

Run the standard delivery loop and commit with `chore(quality): enforce provider quality gates`.

## Acceptance Criteria

- Secrets, credentials, and sensitive SQL values are not exposed.
- Recovery guidance covers failed and unknown-status migrations.
- Concurrent applies are clearly rejected or documented as unsupported.
- Static analysis, race tests where supported, and coverage gates run in CI.
- Coverage is at least 80% for provider code or exclusions are documented.
- Checks and commit are complete.
