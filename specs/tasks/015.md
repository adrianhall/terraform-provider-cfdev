# 015 — PR and release CI/CD

## Introduction

Implement GitHub pull-request validation and tagged provider release automation.

## Details

This is the next-to-last implementation step. Validate branch protection expectations, repository secrets, signing prerequisites, and workflow/tool versions. Write workflow or dry-run checks for PR tests, lint, format, Terraform example validation, coverage >=80%, acceptance gating, generated-doc drift, GoReleaser artifacts, checksums, signatures, and Registry manifests. Implement least-privilege GitHub Actions workflows and Registry ingestion.

Run the standard delivery loop plus release dry-runs and commit with `ci(github): add pull request and release pipelines`.

## Acceptance Criteria

- Pull requests run format, lint, validation, tests, coverage, docs drift, and example checks.
- Acceptance tests are gated behind credentials and explicit safeguards.
- Version tags build correctly named provider archives.
- Checksums, GPG signatures, and Registry manifest are produced.
- Release workflow publishes signed GitHub artifacts and supports Registry ingestion.
- Workflow permissions and secrets follow least privilege.
- Dry-runs, checks, coverage, and commit pass.
