# 007 — Migration-table compatibility

## Introduction

Implement the exact Wrangler-compatible migration table behavior.

## Details

Validate the D1 client seam. Write tests for safe table identifier quoting, creation of the exact schema, `ORDER BY id` reads, the unique `name` constraint, `CURRENT_TIMESTAMP`, and schema mismatch diagnostics. Use the pinned Wrangler 4.151.0 schema for `d1_migrations` and custom tables.

Run the standard delivery loop and commit with `feat(d1): support wrangler migration table`.

## Acceptance Criteria

- Default table is `d1_migrations`.
- Schema is `id INTEGER PRIMARY KEY AUTOINCREMENT`, `name TEXT UNIQUE`, and `applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL`.
- Identifiers are safely quoted.
- Applied migrations are read in `id` order.
- Existing incompatible tables produce actionable diagnostics.
- No provider-only columns are added to shared tables.
- Tests, checks, and coverage pass.
